# Template Form Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Improve Django-rendered ERP templates with consistent form sizing, icons, placeholders, and client-side masks.

**Architecture:** Keep the implementation centralized in the existing generic form metadata builder, generic resource form template, and global CSS/JS assets. Avoid editing each app template unless it is a manual authentication/control-plane template that does not use the generic resource form.

**Tech Stack:** Python, Django forms, Django templates, Bootstrap 5, Feather icon classes, vanilla JavaScript, pytest/Django TestCase.

## Global Constraints

- Preserve existing tenant/resource architecture.
- Do not add frontend dependencies.
- Do not change database schema or migrations.
- Keep CPF/CNPJ server validation intact.
- Keep generated HTML accessible with visible labels, `aria-hidden` decorative icons, and existing error/help wiring.
- Preserve existing local changes in `base/ui/forms.py`.

def test_widget_metadata_adds_specific_placeholders_and_icons(self):
    document_field = forms.CharField(label='CPF/CNPJ')
    _apply_widget_metadata('document', document_field)
    assert document_field.widget.attrs['placeholder'] == '000.000.000-00 ou 00.000.000/0000-00'
    assert document_field.widget.attrs['data-icon'] == 'feather-file-text'

    email_field = forms.EmailField(label='Email')
    _apply_widget_metadata('email', email_field)
    assert email_field.widget.attrs['placeholder'] == 'nome@empresa.com'
    assert email_field.widget.attrs['data-icon'] == 'feather-mail'

    date_field = forms.DateField(label='Validade')
    _apply_widget_metadata('valid_until', date_field)
    assert date_field.widget.attrs['data-icon'] == 'feather-calendar'
